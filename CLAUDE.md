# RamenNearYou — Project Notes

## Ad network compliance — REQUIRED footer links

The site's ads are served by **Mediavine** (it moved off Google AdSense; the AdSense
loader and ad units are gone). Mediavine requires the same set of policy pages AdSense
did, so this requirement is unchanged: the footer (`components/footer.tsx`) **must
always** include these links. Do not remove them:

- Home → `/`
- About → `/about`
- Contact → `/contact`
- Disclaimer → `/disclaimer`
- Privacy → `/privacy-policy`
- Terms → `/terms-of-service`
- Sitemap → `/sitemap.xml`

If asked to trim or restructure the footer, preserve all of the above (they currently
live in the footer bottom bar).

## Fully static site — no server

The site is a Next.js **static export** (`output: 'export'` in `next.config.mjs`),
deployed the same way as pumpkinpatchesnearme.com: `npm run build` writes plain
HTML/JSON into `out/` and Vercel serves those files. There are no API routes, no
middleware/proxy, no server actions, no ISR, and no logins. Keep it that way:

- Anything that needs request-time data runs in the browser: analytics insert
  straight into Supabase with the anon key (`lib/analytics-client.ts`), the
  dashboard reads Supabase from the browser, search/nearby/map read static
  JSON written at build time under `app/data/*` (served at `/data/...`).
- Forms open a pre-filled email (`lib/mailto.ts`) instead of posting anywhere.
- Redirects and headers live in `vercel.json`, generated by
  `scripts/generate-vercel-json.ts` (rerun it after changing redirect rules).
- `scripts/check-static-build.mjs` enforces this: `npm run build` runs it
  before `next build` (source: `output: 'export'`, no `revalidate`,
  `dynamic = 'force-dynamic'`, `dynamicParams = true`, `runtime`, server
  actions, next/cache revalidation, cookies()/headers(), middleware/proxy,
  `api/` dirs, non-`force-static` or non-GET route handlers, vercel.json
  `functions`/`crons`/`rewrites`/`routes`) and after it (prerender manifest has
  no revalidating or fallback routes, no functions in out/, no redirect shadows
  a built page, every retired redirect lands on a built page). A failure fails
  the deploy. ISR writes are why listings were cut in 2026; don't weaken it.
- Not every template page is built (`lib/retired-pages.json`). Retired pages
  are real 308s: generate-vercel-json.ts packs the retired map into
  `/:retired(...)` rules in vercel.json (one per target; vercel.json allows
  2,048 rules of up to 4,096 chars). `scripts/resolve-dead-links.mjs` runs
  after `next build` and rewrites any internal link to a page that isn't
  built to its live destination.
- Listing lookups in lib/restaurants.ts are indexed by slug; keep new
  per-page helpers off linear scans of the whole dataset.
- Content changes (dataset, Supabase rows read at build) appear only after a
  redeploy.
